# Security Policy

## Reporting a Vulnerability

If you discover a security issue in linux-update, please open a private security report through GitHub Security Advisories or contact the maintainer.

Please include:

- affected version
- operating system
- reproduction steps
- impact assessment

Do not publish exploitation details before a fix is available.

---

## Supported Versions

| Version | Status |
|----------|----------|
| 0.6.x | Supported |
| 0.5.x | Limited support |
| < 0.5.0 | Unsupported |

---

## Release Integrity

All official releases are published through GitHub Releases.

Release assets include:

- DEB packages
- RPM packages
- AppImage builds
- Cosign signatures
- Provenance metadata

---

## Artifact Verification

Each artifact includes a corresponding Cosign signature:

```text
linux-update_VERSION.deb.sig
linux-update_VERSION.rpm.sig
linux-update_VERSION.AppImage.sig
```

Verify a downloaded artifact:

```bash
cosign verify-blob \
  --signature linux-update_VERSION.deb.sig \
  linux-update_VERSION.deb
```

---

## Keyless Signing

linux-update uses:

- Cosign
- Sigstore
- GitHub OIDC

Release artifacts are signed using keyless signatures generated by GitHub Actions.

No long-lived signing keys are stored in the repository.

---

## Provenance

Each release contains:

```text
provenance.json
provenance.json.sig
```

The provenance document contains:

- version
- git commit
- workflow name
- repository
- build timestamp
- artifact hashes

Verify:

```bash
cosign verify-blob \
  --signature provenance.json.sig \
  provenance.json
```

---

## Security Scope

The following data is not collected by linux-update:

- usernames
- passwords
- email addresses
- personal files
- browsing activity

Future telemetry features, if introduced, will be opt-in and documented separately.

---

## Disclosure Policy

Security fixes may be released without prior public disclosure.

Critical vulnerabilities may result in immediate releases outside the normal release cycle.
